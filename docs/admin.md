# 后台管理端

管理端为独立的 Spring Boot 工程，端口 8081，与 8080 用户端共享 `fangcun_forest` 数据库。已提供管理代码和页面；构建、JUnit、应用启动与真实数据库验收仍由用户执行。

## 首次准备管理员

本次不改表结构，不清库。已有数据库只需执行 `database/04-demo-admin.sql` 添加教学管理员；脚本不会覆盖已有同名账号、密码或角色。新的空库按 01、02、03、04 顺序初始化。

也可在项目根目录使用已有交互式初始化脚本，会保留已有数据与配置：

```powershell
cd D:\上机实验\MyStore
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Initialize-Database.ps1
```

脚本需要输入 MySQL 密码，这是数据库连接密码，与下面的商城/管理员登录密码不同。若尚未配置应用连接，可使用 `-ConfigureApplications`；已有本机配置不覆盖。

教学管理员：`forest_admin`，密码 `Forest2026!`。这是 ADMIN 角色，普通商城账号 `forest` 不能登录后台。

## 创建和编辑自己的管理员

当前管理界面中的管理员账号只读，普通用户维护表单不能改角色或管理员密码。自定义管理员可按以下步骤创建：

1. 在用户端 `http://localhost:8080/register` 注册想使用的账号和密码，系统生成 BCrypt 散列。
2. 用 Navicat 打开 `fangcun_forest` 数据库，执行下面的 SQL，把用户名换成刚注册的账号：

```sql
UPDATE store_user
SET role = 'ADMIN', status = 'ENABLED'
WHERE username = '你的用户名';
```

3. 用该账号和注册时的密码登录 `http://localhost:8081/`。改为 ADMIN 后，此账号不再作为普通商城用户登录用户端。

在 Navicat 的 `store_user` 表中，可按 `username` 定位管理员，修改 `display_name`（昵称）、`email`、`phone`，保存后重新登录。例如：

```sql
UPDATE store_user
SET display_name = '我的管理员', email = 'admin@example.com'
WHERE username = '你的用户名' AND role = 'ADMIN';
```

不要修改账号 ID，也不要把明文密码写进 `password_hash`。当前后台页面没有管理员密码重置功能；普通商城用户密码重置仍可通过用户维护页面完成。

## 页面和功能

| 地址 | 内容 |
| --- | --- |
| `/login` | 独立管理员登录与退出提示 |
| `/` | 实际数据库统计、低库存数量、待发货数量、模拟成交额 |
| `/categories`、`/categories/new`、`/categories/{id}/edit` | 分类查询、添加、修改与删除 |
| `/products`、`/products/new`、`/products/{id}/edit` | 商品查询、添加、修改、封面上传、删除、上下架、相册及增量补货 |
| `POST /media/covers` | ADMIN + CSRF 验证的封面上传，返回本地图片路径及尺寸 |
| `/users`、`/users/{id}` | 账号查询、商城用户资料/状态维护、密码重置 |
| `/orders`、`/orders/{id}` | 订单查询、收货信息修改、取消、删除已取消订单、发货 |

沿用本项目的两级分类与单 SKU 模型：一级分类对应 Category，二级商品类型对应 Product 层次，`product` 表中的单 SKU 商品对应 Item。没有引入破坏现有商品和订单数据的新三层表结构。

## 商品与分类规则

- 分类仅两级；父分类必须是一级分类，不能以自身为父分类。有子分类或商品引用时不能删除。分类编码及父子关系创建后固定，只能编辑名称和排序。
- 分类编码全局唯一，同一父分类下的名称唯一。修改带字段修订摘要，过期页面不能覆盖新资料。
- 商品只能属于二级分类。新增先保存为 DRAFT，再明确上架；零库存可上架展示售罄。
- SKU 唯一，价格大于零且最多两位小数。商品资料编辑不写库存，补货使用独立的数据库增量更新，锁定最新商品后增量更新并检查溢出上限，不依赖页面旧版本；资料编辑仍检查版本。
- 封面可在新增、编辑页直接选择本机 JPG/PNG，自动上传、回填路径和预览。上传成功后仍需保存商品资料。单文件不超过 5MB、单边不超过 6000 像素、总像素不超过 1200 万；服务端核验真实格式、重新编码像素并生成随机文件名。上传中不能保存；失败可重试、重新选图或取消本次选择，不会静默替换当前封面。
- 两端通过 `/images/uploads/` 读取共用目录，默认 `${user.home}/.fangcun-forest/uploads`，可用同一个绝对路径的 `FOREST_UPLOAD_DIR` 覆盖。两端应以同一系统用户运行；若使用不同用户、容器或机器，必须额外配置可共同读取的持久化目录。重启与重新构建不会删除上传图；删除商品或更换封面不自动删除旧文件，取消表单的上传也会保留，以免破坏历史订单图片。
- 封面仍可手填 `/images/` 本地路径，相册最多 8 张，路径换行分隔；相册没有批量上传控件，可复用已有上传路径。九件示例商品与占位图仍在两端静态目录，例如 `/images/products/fc-forest-001.png`、`/images/terrarium.svg`，完整路径见 [素材说明](assets.md)。不提供远程图片代理。
- 删除商品须已下架且没有购物车或订单明细引用；被引用商品保留下架状态，不破坏历史成交快照。

手工添加新品可使用 [示例封面与完整填写步骤](../examples/README.md)。新增保存为未上架状态，检查预览后再上架；本次无需执行任何数据库迁移或清库脚本。

## 用户与身份规则

- 账号查询可查看用户名、昵称、角色、状态、邮箱、电话；密码和散列不输出到页面。
- 普通商城用户可修改昵称、邮箱、电话、启停状态，并重置密码。用户名与角色不通过此表单修改；管理员账号在此页面只读。
- 新密码需两次一致，8—64 个字符且 UTF-8 不超过 72 字节，使用 BCrypt 保存，不在错误页面回填。
- 用户端每次动态请求核对账号角色、状态和密码散列指纹；禁用或重置密码后，旧会话在下一次请求时失效。
- 管理端只接受 ADMIN，所有管理读写 URL 都受角色校验；写操作仍要求 CSRF。两个工程使用不同 Session Cookie，登录时更换 Session ID，退出清空会话。

## 订单规则与双端协作

1. 用户端下单时扣库存并保存成交快照，模拟支付后状态 PAID。
2. 管理端仅允许对 PENDING_PAYMENT、PAID 订单修改收货信息，不直接改金额、商品快照或任意切换状态。
3. PAID 订单可发货，变为 SHIPPED 并记录时间；发货不再次扣库存。
4. 用户收到后在用户端确认收货，变为 COMPLETED。
5. 待付款可由用户或管理员取消，与库存恢复处于同一事务，不能重复归还。
6. 只允许删除 CANCELLED 订单及其明细；删除不再变更库存，已付款和履约记录保留。

后台订单操作沿用用户端的锁顺序：先用户，再订单，涉及归还库存时按商品 ID 升序处理。用户购买、管理员补货、支付/取消与发货同时操作时，依靠数据库锁和版本/状态条件处理竞争；页面过期时要求刷新。

## 额外功能

- 实时工作台：分类、商品、上架数、订单数、商城用户数、待发货数、低库存数及模拟支付成交总额。
- 商品低库存突出显示与独立增量补货。
- 管理写操作的 AOP 日志，日志名 `ADMIN_AUDIT`，记录管理员 ID、动作、目标编号与成功/失败；不记录表单内容、密码或收货信息。本次为服务日志，不是独立的不可篡改审计库。

## 待用户运行的验收

- 使用普通商城账号登录后台应失败；未登录不能查看后台列表或直接 POST 写操作；缺少 CSRF 的写请求应拒绝。
- 创建一级、二级分类和新商品，先保存未上架，在用户端不可见；上架后可搜索、加购与购买。
- 编辑资料、补货、下架、删除未引用商品；尝试第三层分类、重复编码/SKU、删除被引用分类或商品，应有提示且数据不变。
- 两个标签页提交旧版本的商品或分类表单，应提示刷新，不能覆盖新数据。用户购买和后台补货同时进行，库存不丢失、不为负。
- 修改商城用户状态，旧用户会话下一次请求失效；重置密码后旧密码和旧会话不可继续使用，新密码可登录。
- 用户端模拟支付，后台按 PAID 筛选并发货，用户端确认收货；未付款订单不能发货。
- 两端同时取消同一待付款订单或支付与取消竞争，库存只归还一次。删已取消订单不再次归还；已付款订单不能删除。
- 多商品事务中制造后续库存恢复失败，确认前面已恢复库存与订单状态整体回滚。
