# 用户端功能与验收

本次补齐商品、用户、购物车订单三个模块。复用原有七张表，已有完整数据库无需重建或重新导入种子数据。构建、启动和测试由用户执行；本文是操作步骤与预期行为，不是已经通过的运行记录。

## 打开项目

在项目根目录运行：

```powershell
.\mvnw.cmd -f forest-storefront/pom.xml test
.\mvnw.cmd -f forest-storefront/pom.xml spring-boot:run
```

打开 `http://localhost:8080/`。已有用户端进程时先 Ctrl+C 停止旧进程，再启动新版本。保留原本已配置成功的 `application-local.yml`；本次未改写数据库密码或初始化现有数据。

## 页面与流程

| 页面 | 功能 |
| --- | --- |
| `/` | 三页森林背景、逐字显现、账号/游客入口 |
| `/register` | 账号、昵称、可选邮箱、密码确认、图片验证码 |
| `/login` | 商城账号密码与图片验证码、显示密码、退出/错误提示 |
| `/main` | 首页分类、精选商品、名称搜索、滚动浮现 |
| `/category` | 一级/二级分类、名称搜索、价格/时间排序、有货筛选、分页 |
| `/product?id=1` | 商品资料、封面/相册切换、数量选择、加入购物车、同类推荐 |
| `/account` | 当前账号、购物车与订单入口 |
| `/cart` | 账号持久化购物车、更新数量、移除、全选/勾选、合计 |
| `/checkout?items=购物车条目ID` | 核对所选商品与收货信息，提交订单 |
| `/orders` | 自己的订单，按状态筛选与分页 |
| `/orders/{id}` | 订单商品快照、收货信息、时间、支付/取消/确认收货 |
| `/orders/{id}/pay` | 明确提示教学模拟支付，勾选确认后付款 |

游客可浏览商品。进入个人账号、购物车或订单时要求登录。教学商城账号仍为 `forest / Forest2026!`，也可以注册新账号；必须输入当前图片验证码。这和 MySQL 管理账号无关。

注册账号为 3—30 位英文字母、数字或下划线；昵称必填，邮箱选填。密码为 8—64 个字符，同时限制 UTF-8 最多 72 字节，数据库保存 BCrypt 散列。注册成功后回到登录表单。验证码两分钟有效，忽略大小写，每次校验即作废；点击图片刷新。它不是短信、邮件或微信验证码。

## 完整购买验收

1. 注册新账号；尝试重复账号、不同的两次密码、错误验证码，确认不会注册成功。检查失败页面不回填密码。
2. 正确登录；尝试错误密码、错误验证码、重复使用旧验证码。点击欢迎页与注册/登录入口，确认左侧文字及背景不重播。
3. 从首页搜索“苔藓”；在商品列表切换一级与二级分类、两种价格排序和仅看有货，翻页后筛选应保留。下架商品 9 仍不能从详情访问；商品 6 显示售罄。
4. 在商品 1 的详情选择数量加入购物车。再次加入同种商品应合并；单项 1—99，最多 20 种，不能超过当时库存。重新登录后购物车仍在。
5. 更新数量、移除条目、勾选部分商品；合计随选择更新。没有选中商品时无法结算。下架或库存不足条目保留提示，可移除但不能结算。
6. 进入结算，填写收货人、电话与地址。提交后只有勾选条目被移出购物车；生成待付款订单、商品快照，库存扣除相应数量。订单金额由服务器使用 BigDecimal 计算，当前免运费。
7. 打开支付页，确认“模拟支付，不会真实扣款”，勾选并提交。订单变为已付款，生成 MOCK 流水，库存不会再次扣除。
8. 另下一笔订单并取消，确认库存恢复。再次取消不会重复归还；已付款订单不能取消；已取消订单不能支付。
9. 订单列表筛选待付款、已付款、已取消；详情展示成交时商品名称、封面和价格，后续商品变更不改写快照。
10. 在管理端将已付款订单发货，用户端显示 SHIPPED 后可确认收货。已付款不能直接跳过发货变为已完成。

## 交易与归属边界

- CSRF 对全部写操作保持启用；GET 不执行加购、支付、取消等写操作。用户 ID 来自当前 Spring Security 身份，不接受表单指定归属。
- 购物车修改带版本号；过期页面提交提示刷新。切换账号后，旧结算凭证不属于新用户，不能下单。
- 结算快照仅保存在当前 Session，最多 6 份，有效 30 分钟。同一有效凭证重复提交由服务器固定订单号与数据库唯一键防止重复下单。
- 下单先锁定用户，再按商品 ID 升序锁定商品。重新检查购物车数量/版本、上下架、价格和库存；失败抛出异常，订单、明细、已扣库存和购物车清理应整体回滚。
- 支付与取消都先锁定用户，并附加待付款状态和版本条件；支付只改订单，取消与库存恢复同事务。
- 订单详情、支付、取消与确认收货均按 `user_id` 查订单。用另一个账号替换订单编号，应返回不存在或拒绝操作，不能读取收货信息。

## 必须使用真实 MySQL 验证的场景

下面步骤建议使用专门的实验库与两个测试账号，记录操作前后的库存、订单状态、版本号与行数。提供的 Mapper 模拟测试不证明数据库回滚或并发正确。

- 在结算后、提交前修改购物车数量或商品价格：提交应要求重新确认，不产生新订单或库存变化。
- 多商品结算中，让第二件商品库存不足：第一件已经执行的库存扣减也应回滚，购物车与订单表保持原状。
- 两个账号同时购买最后一件库存：最多一个成功，库存不小于零。
- 两个标签页重复提交同一结算凭证：只生成一笔订单，只扣一次库存，只移除一次条目。
- 对同一笔待付款订单并发提交支付与取消：最终只出现一个合法状态；取消时归还一次，支付时不归还。
- 两个标签页用旧购物车版本更新/移除：过期操作提示刷新。
- 用另一个账号的购物车条目和订单 ID 请求读写：不能越权。
- 退出后用旧页面提交：不能继续写当前账号数据；省略 CSRF 字段应拒绝。

只读核对 SQL：

```sql
SELECT id, sku, stock, version FROM product ORDER BY id;
SELECT id, user_id, product_id, quantity, version FROM cart_item ORDER BY id;
SELECT id, order_no, user_id, status, total_amount, payment_method, version
FROM sales_order ORDER BY id DESC;
SELECT order_id, product_id, unit_price, quantity, line_amount
FROM sales_order_item ORDER BY order_id DESC, product_id;
```

## 当前范围

支付为教学模拟支付，不连接真实微信、支付宝或银行卡；没有实际物流、退款、短信、邮件验证码、找回密码和优惠券。待付款订单暂不自动超时取消，需要用户或管理员主动取消以归还库存。管理端鉴权、发货、补货和资料维护见 [管理端说明](admin.md)。

商品页提供原位退出确认；游客点击购物车、订单或加入购物车时统一先渐隐进入登录，登录后返回对应页面。首页、列表、详情、分页筛选与浏览器返回也使用统一的 280ms 渐隐、360ms 渐显，细节见 [登录行为说明](login.md)。

JUnit/MockMvc 用例已提供：登录/CSRF、验证码单次使用、注册角色与密码散列、购物车库存/版本、订单快照/金额、重复提交、非法状态等。本轮不执行 Maven 构建、JUnit 或 Spring Boot 启动，只做源码、资源与静态页面检查。

实现参考：[Spring Security FilterChain](https://docs.spring.io/spring-security/reference/6.5/servlet/architecture.html)、[MyBatis-Plus 乐观锁插件](https://baomidou.com/plugins/optimistic-locker/)。自定义库存和订单条件更新在 SQL 中显式处理版本号。
